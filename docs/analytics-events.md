# Аналитические события сторис

Раздел 9 ТЗ. Схемы — `packages/schema/src/events.ts` (zod), JSON Schema — в `docs/openapi/public.openapi.json`
(`StoryEvent`). Приём — `POST /v1/events`.

## Приём

```
POST {PUBLIC_API}/v1/events
Content-Type: application/json

{ "events": [ { …событие… }, … ] }     — от 1 до 50 событий, тело не больше 64 КБ
→ 202 { "accepted": N, "rejected": M }
```

- Каждое событие проверяется отдельно: невалидные отбрасываются и считаются в `rejected`, остальные принимаются.
- Дедупликация по `event_id` 24 часа: повтор уже принятого события считается принятым (можно безопасно
  ретраить батч целиком). Неизвестные поля отбрасываются.
- `413` — тело больше 64 КБ, `429` — превышен лимит запросов, `503` — очередь приёма недоступна (ретрай позже).
- Дальше события: сырые — 30 дней в сервисе, дневные агрегаты — 2 года (статистика админки), копия уходит
  в аналитику ИДБ через адаптер с ретраями (открытый вопрос №4).
- Если на платформе события уже уходят в аналитику ИДБ напрямую, этот эндпоинт можно не использовать —
  но для статистики в админке нужны минимум `story_slide_view` и `story_cta_click`.

## Общие поля

| Поле | Тип | Описание |
|---|---|---|
| `event_id` | uuid v4 | Уникален для события, для дедупликации |
| `event` | string | Имя события |
| `ts` | ISO 8601 | Время на клиенте (для дневной статистики учитывается, если отличается от времени приёма не больше чем на сутки) |
| `session_id` | string ≤ 128 | Сессия приложения |
| `platform` | `ios` \| `android` \| `web` | |
| `app_version` | string ≤ 32 | |
| `placement` | `home` \| `catalog` \| `product` \| `cart` | |
| `group_id`, `group_version` | uuid, int ≥ 1 | Где применимо |
| `slide_id`, `slide_index`, `slide_type` | uuid, 0–9, string | Где применимо; `slide_type` — строка, клиент может знать тип, которого не знает сервер |

**Идентификатор пользователя не передаётся** (152-ФЗ, раздел 10.7): связь с пользователем делает система
аналитики ИДБ своими средствами.

## События

| Событие | Когда | Поля кроме общих |
|---|---|---|
| `stories_feed_shown` | Ряд кружков попал во вьюпорт | `groups_count`; `group_ids` — ID видимых кружков (расширение ТЗ, нужно для «Показов кружка») |
| `story_group_open` | Открыта группа | `group_id`, `group_version`, `source: tap\|swipe\|auto` |
| `story_slide_view` | Слайд показан ≥ 1 с | группа + слайд |
| `story_slide_complete` | Слайд досмотрен до конца | группа + слайд |
| `story_cta_click` | Клик по CTA (после проверки allowlist) | группа + слайд, `cta_type`, `cta_value` |
| `story_product_click` | Клик по карточке товара | группа + слайд, `sku` |
| `story_add_to_cart` | «В корзину» из слайда | группа + слайд, `sku` |
| `story_close` | Закрытие плеера | группа, `reason: swipe\|button\|end`, `watched_slides` |
| `story_media_error` | Медиа не загрузилось или с чужого хоста | группа + слайд, `error_code` (`[A-Za-z0-9_.:-]{1,64}`) |

Пример:

```json
{
  "event_id": "5f0c1c8e-3a2b-4d61-9d36-0c0f9b1e2a77",
  "event": "story_cta_click",
  "ts": "2026-10-01T09:00:12.345Z",
  "session_id": "s-8c1f",
  "platform": "ios",
  "app_version": "5.12.0",
  "placement": "home",
  "group_id": "7c1e3d9a-1111-4a2b-8c3d-000000000001",
  "group_version": 3,
  "slide_id": "0b1d2c3e-2222-4a2b-8c3d-000000000002",
  "slide_index": 0,
  "slide_type": "image",
  "cta_type": "category",
  "cta_value": "cat_123"
}
```

## Статистика в админке

| Метрика | Источник |
|---|---|
| Показы кружка | `stories_feed_shown.group_ids` |
| Открытия, open rate | `story_group_open` / показы |
| Воронка досмотра | `story_slide_view` и `story_slide_complete` по слайдам; охват слайда = просмотры / открытия |
| CTR на CTA | группа: клики CTA / открытия; слайд: клики CTA / просмотры слайда |
| Добавления в корзину | `story_add_to_cart` |

Сутки считаются по Москве. Агрегаты строятся только по реально принятым событиям: ретрай батча и повторная
обработка очереди не удваивают счётчики. События о несуществующих группах в статистику не попадают.

## Атрибуция покупок

Параметр `story_ref=<group_id>:<slide_id>` добавляется к диплинку/ссылке CTA и прокидывается приложением
в события корзины и заказа. Модель и окно атрибуции считает аналитика ИДБ (открытый вопрос №4).
