# Контракт плееров сторис (web, iOS, Android)

Документ для мобильных команд ИДБ (раздел 8 ТЗ). Эталонная реализация — веб-плеер `packages/web-player`.
Машиночитаемая схема ответа — `docs/openapi/public.openapi.json` (`FeedResponse`), события — `docs/analytics-events.md`.

## 1. Запрос ленты

```
GET {PUBLIC_API}/v1/feed?placement=home
X-Platform: ios | android | web          — обязательно
X-App-Version: 5.12.0                     — обязательно для ios и android (форматы 5, 5.12, 5.12.0)
Authorization: Bearer <токен ИДБ>         — необязательно; без токена — анонимная лента
```

- `placement`: `home`, `catalog`, `product`, `cart` (список уточняется, открытый вопрос №7).
- `400` — нет обязательных заголовков или параметра. `429` — превышен лимит запросов.
- Анонимный ответ кешируется CDN (`Cache-Control: public, max-age ≤ 60`). С токеном —
  `Cache-Control: private, no-store`: такой ответ нельзя класть в общий кеш.
- Токен сервис не хранит и не логирует. Невалидный токен не даёт ошибки — просто вернётся лента без
  таргетированных групп.

## 2. Ответ

```json
{
  "schema_version": 1,
  "generated_at": "2026-10-01T09:00:00Z",
  "ttl_sec": 60,
  "groups": [ { "id": "…", "version": 3, "title": "…", "cover": { "url", "w", "h" }, "slides": [ … ] } ]
}
```

| Поле | Правило для клиента |
|---|---|
| `schema_version` | Больше поддерживаемого клиентом (сейчас 1) → **скрыть блок ленты целиком** |
| `ttl_sec` | Хранить последний успешный ответ до `ttl_sec` секунд, не чаще запрашивать заново |
| `groups` | Уже отсортированы сервером (priority, затем дата старта). Не больше 20 групп, до 10 слайдов |
| `groups[].version` | Меняется при каждой новой согласованной версии группы |
| `slides[].type` | `image`, `video`, `product`. **Неизвестный тип — пропустить слайд молча** |
| `slides[].elements[].kind` | Сейчас `text`. **Неизвестный kind — пропустить элемент молча** |
| неизвестные поля | Игнорировать (сервер добавляет поля без смены `schema_version`) |

Слайды:

- `image`: `media.variants[]` — `{url, w, h, mime}`; есть `image/webp` (1080×1920, 720×1280) и
  `image/jpeg`-фолбэк тех же размеров. Выбирать WebP, если платформа поддерживает; ширину — ближайшую
  не меньше ширины экрана в пикселях.
- `video`: `media.variants[]` — MP4 H.264/AAC 1080p (~2500 kbps) и 720p (~1200 kbps) с `bitrate_kbps`;
  `media.poster` — кадр для показа до старта воспроизведения. `duration_ms` = длительность файла (≤ 60 с).
- `product`: `product_skus` (1–6). Цены, названия, наличие **в ленте нет** — запросить каталог ИДБ по SKU
  в момент показа. Нет в наличии → скрыть карточку; не осталось товаров → пропустить слайд.
- `elements[]` (`kind: text`): `text`, `style` (`title`, `body`, `caption`), `position` (`top`, `center`, `bottom`).
- `cta`: `{type, value, label}` или `null`. Типы: `deeplink`, `product` (SKU), `category` (ID), `url` (https).

## 3. Лента (ряд кружков)

- Горизонтальный ряд: обложка `cover` + `title`.
- Просмотренные группы приглушены и сдвинуты в конец ряда. «Просмотрено» хранится локально по ключу
  `group_id + version`: новая версия группы снова непросмотрена.
- Сервис недоступен, ошибка сети, невалидный JSON, пустой `groups` или неподдерживаемый `schema_version` →
  блок ленты скрывается. Приложение не падает и не показывает ошибку.
- Событие `stories_feed_shown` — когда ряд попал во вьюпорт (с `group_ids` видимых кружков).

## 4. Плеер

- Полноэкранный; сверху прогресс-бар из сегментов по числу слайдов.
- Тап справа — следующий слайд, тап слева — предыдущий. Удержание — пауза. Свайп вниз — закрыть.
  Свайп влево/вправо — соседняя группа. После последнего слайда — следующая группа, после последней — закрыть.
- Автопереход по `duration_ms`; видео — по окончании. Пока видео буферизуется, таймер стоит.
- Предзагрузка: следующий слайд и обложка следующей группы.
- Доступность: подписи для скринридеров (заголовок группы, текст слайда), видимая кнопка закрытия.
  При включённом reduce motion — без автоперехода и автозапуска видео.

## 5. Безопасность на клиенте (обязательно)

1. **Текст — только plain text** нативными средствами (UILabel/TextView). HTML и Markdown не интерпретировать,
   WebView для текста не использовать. Строка `<script>alert(1)</script>` должна отобразиться как есть.
2. **Медиа — только с CDN-домена из конфигурации приложения.** URL с другого хоста игнорировать (слайд
   пропустить, событие `story_media_error` с `error_code=forbidden_origin`).
3. **CTA перед переходом проверить ещё раз по allowlist** (тот же алгоритм, что на сервере,
   `packages/schema/src/allowlist.ts`):
   - `deeplink`: схема — только из списка приложения (открытый вопрос №6; сейчас `idb`); без логина/пароля в URL.
   - `url`: только `https`; хост после нормализации (нижний регистр, punycode) равен разрешённому домену
     или его поддомену; без userinfo (`https://iledebeaute.ru@evil.com`), без IP-адресов, без порта;
     без пробелов, управляющих символов и обратного слэша.
   - Всегда запрещены `javascript:`, `data:`, `file:`, `intent:` и любые схемы вне списка.
   - `product` / `category`: значение `[A-Za-z0-9_-]{1,64}`, переход — внутренней навигацией приложения.
   Не прошло проверку — не переходить.
4. К диплинку и `url` добавить параметр атрибуции `story_ref=<group_id>:<slide_id>` (заменив, если он уже есть),
   и прокинуть его в события корзины и заказа приложения.

## 6. События

Список, поля и правила — `docs/analytics-events.md`. Для статистики в админке нужны как минимум
`story_slide_view` и `story_cta_click`. Идентификатор пользователя в события не передаётся.
