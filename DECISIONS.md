## 2026-09-28 — Версии стека

**Контекст.** Раздел 3.1 задаёт стек без версий. На дату начала вышли мажоры, API которых ещё не устоялся
(TypeScript 7 на Go без JS API для typescript-eslint, Prisma 7/8 с новым генератором, Vitest 5).
**Решение.** Node 22 LTS в образах и CI, TypeScript 5.9, Fastify 5, zod 4, Prisma 6.19, BullMQ 5, ioredis 5,
Vite 7, React 19, Vitest 3, ESLint 10, pnpm 10 (`minimumReleaseAge` сутки — защита от свежих вредоносных релизов).
Обновления — Renovate с задержкой 3 дня и ручным одобрением мажоров.
**Альтернативы.** Самые свежие мажоры — выше риск несовместимостей без выигрыша для MVP.

## 2026-09-28 — Локальное S3: RustFS вместо MinIO

**Контекст.** ТЗ: «локально MinIO». Репозиторий `minio/minio` на Docker Hub удалён, бинарники на dl.min.io
отдают 410 — MinIO перестал распространять сборки community-версии.
**Решение.** В `docker compose` — RustFS 1.0.0 (S3-совместимый, Apache-2.0, закреплён по digest). Бакеты,
политики, CORS и lifecycle создаются стандартным S3 API (`apps/api/src/scripts/storage-init.ts`), поэтому
подойдёт любое S3-совместимое хранилище, включая прод в РФ-контуре.
**Альтернативы.** SeaweedFS, Garage (нестандартные политики доступа), старый образ MinIO из зеркал (не обновляется).

## 2026-09-28 — Три бакета вместо двух

**Контекст.** Раздел 7: воркер пишет в public bucket, но черновые медиа не должны попадать в CDN-путь
до публикации (T5, 7.4).
**Решение.** `quarantine` (оригиналы, закрыт) → воркер → `media` (обработанные черновики, закрыт, только
подписанные URL на 15 минут) → при публикации копия в `public` (origin CDN) под тем же непредсказуемым
ключом. Права воркера: чтение quarantine, запись media. Копирование в public делает API/планировщик.
**Альтернативы.** Один публичный bucket с префиксами и политикой только на `p/*` — ошибка в одной политике
раскрывает все черновики.

## 2026-09-28 — Медиа-воркер без БД; отдельный процесс фоновых задач

**Контекст.** 10.5: у воркера нет сети, кроме S3, и минимум прав. Фоновым задачам (планировщик, события)
нужна БД.
**Решение.** `apps/worker` собирается в два образа: `media` (ffmpeg/libvips; сеть — только Redis-очередь
и S3; в compose — внутренняя сеть без выхода наружу) и `jobs` (БД, планировщик, события, ретеншн).
Результат обработки уходит в очередь `media-results`, её разбирает `jobs`. RCE в декодере не даёт доступа к БД.
TODO(spec): в проде ограничить Redis-пользователя воркера ACL на ключи `bull:media-*`.
**Альтернативы.** Воркер с доступом к БД — шире радиус поражения при T2.

## 2026-09-28 — Дополнительные пакеты `packages/core` и `packages/db`

Публикация, кеш ленты, аудит нужны и API, и планировщику; Prisma-схема — API и jobs. Вынесены в пакеты,
чтобы приложения не импортировали друг друга.

## 2026-09-28 — Правило четырёх глаз строже буквы ТЗ

**Контекст.** 10.3: согласует публикатор, который «не является автором последней правки». Обход: A вносит
вредную правку, B правит опечатку — «последний автор» теперь B, и A согласует сам.
**Решение.** Храним `editorsSinceApproval` — всех, кто правил рабочую копию с последнего согласования;
никто из них не может согласовать. Согласование привязано к `revision`, которую видел публикатор:
если группу поменяли после открытия экрана согласования — 409. Проверка под `SELECT … FOR UPDATE`.
**Альтернативы.** Буквальное правило — оставляет обход через соавтора.

## 2026-09-28 — Жизненный цикл: уточнения

- Правка группы в любом статусе → `draft`, `revision+1`. Опубликованный снимок продолжает показываться.
- Правка после согласования **отменяет** ещё не опубликованный снимок (`superseded`): в ленту не уйдёт версия,
  которую команда уже решила менять. Альтернатива — публиковать старую согласованную версию по расписанию.
- Если при согласовании `start_at` уже наступил, публикация выполняется сразу («наступление start_at», 4.2).
- Ручная публикация до `start_at` допустима (копирует медиа в public), но лента всё равно фильтрует по `start_at`.
- Снятие с публикации архивирует и опубликованный, и ожидающий снимки.
- Удалить можно только группу, которая ни разу не согласовывалась; остальное — снятие с публикации.
- CTA проверяется по allowlist при сохранении, отправке, согласовании и публикации (включая автопубликацию
  планировщиком: если allowlist сузили, публикация блокируется и пишется событие безопасности).

## 2026-09-28 — Модель данных

- CTA хранится отдельной колонкой `slide.cta`, `elements` — массив с дискриминатором `kind` (сейчас `text`;
  опросы/квизы добавятся новым вариантом). Так проще валидировать CTA отдельно по allowlist.
- В снимке хранится `source` — нормализованная рабочая копия на момент согласования; по ней считается diff
  для очереди согласования. Снимок и `source` защищены триггером от изменений.
- Длина текстов считается в UTF-16 code units (консервативно). Запрещены управляющие и bidi-символы.
  TODO(spec): лимиты текста слайда (140 символов, до 3 элементов) не заданы в ТЗ.
- Admin API — camelCase, публичный API — snake_case.

## 2026-09-28 — Медиа

- Presigned **PUT** (как в ТЗ) с подписанными `Content-Type` и `Content-Length`: размер фиксируется ровно
  заявленным (≤ лимита); воркер повторно проверяет размер, тип и содержимое.
- Тип по сигнатуре; заявленный тип должен совпадать с реальным (PNG под видом JPEG — отказ); MP4 и MOV — одно семейство.
- Polyglot: поиск маркеров разметки длиной ≥ 6 байт (вероятность ложного срабатывания в сжатых данных ничтожна);
  основная защита — обязательное перекодирование.
- libvips: разрешены только загрузчики JPEG/PNG/WebP (`sharp.block`), `VIPS_BLOCK_UNTRUSTED=1`, лимит пикселей,
  размеры сначала читаются из заголовка без декодирования и сверяются с libvips.
- Изображения обрезаются по центру до точных 1080×1920 и 720×1280 (при необходимости с увеличением).
  TODO(spec): минимальный размер обложки не задан — 256×256; обложка загружается отдельно (`purpose=cover`).
- Видео: H.264/HEVC + AAC/MP3; один проход декодера на оба варианта; постер из нашего перекодированного файла.
  ffmpeg в образе собран из исходников (sha256) с `--disable-network`, только mov-демуксер; при запуске
  дополнительно `-protocol_whitelist file -f mov`. libx264 (GPL) — образ внутренний, не распространяется.

## 2026-09-28 — Лента и кеш

- Кеш ответа в Redis адресуется «поколением» `feed:gen`: публикация, снятие, kill switch увеличивают его —
  изменения видны сразу во всех инстансах; старые ключи истекают сами (TTL ≤ 60 с).
- `app_version_bucket` = номер ступеньки среди порогов `min_app_version` опубликованных групп: версии в одном
  бакете гарантированно получают одинаковую ленту.
- `ttl_sec` и `max-age` не больше времени до ближайшего `start_at`/`end_at`, поэтому группа не видна до старта
  даже из кеша.
- Любой запрос с `Authorization` (даже с невалидным токеном) получает `Cache-Control: private, no-store`.
  Для CDN выставлен `Vary: Authorization, X-Platform, X-App-Version`; нормализация версии в ключе CDN —
  [ИНТЕГРАЦИЯ] с CDN ИДБ.
- Без Redis лента работает из БД (набор снимков в памяти процесса перечитывается не чаще раза в 5 с).
- Размер ответа < 100 КБ трактуется как размер передачи: API всегда сжимает ответ (br/gzip). Худший случай —
  20 групп × 10 слайдов с максимальными текстами — ≈ 350 КБ JSON, ≈ 36 КБ gzip, ≈ 29 КБ br
  (`packages/core/test/feed-size.test.ts`). Типичный ответ — единицы килобайт. Альтернатива (обрезать ленту
  до 100 КБ без сжатия) молча выкидывала бы согласованные группы.

## 2026-09-28 — События и статистика

- `stories_feed_shown` расширено необязательным `group_ids` — без него нельзя посчитать «показы кружка».
  Версия в событии не передаётся, показы хранятся в агрегате с `group_version = 0`.
- Дубликаты по `event_id` считаются принятыми (идемпотентность для ретраев клиента).
- Сырые события и агрегаты пишутся в одной транзакции; агрегируются только реально вставленные события, так
  что ретрай задачи не удваивает счётчики. События о несуществующих группах в агрегаты не попадают (T8).
- День в статистике — по Москве; время клиента принимается, если оно в пределах суток от времени приёма.
- CTR группы = клики CTA / открытия; CTR слайда = клики CTA / просмотры слайда.

## 2026-09-28 — Аутентификация, сессии, роли

- SSO — интерфейс `SsoAdapter` + mock-IdP (страница выбора сотрудника, только dev; в production конфиг
  не стартует). Реальный OIDC/SAML — открытый вопрос №3.
- Роли хранятся в БД и назначаются администратором; маппинг групп IdP — TODO(spec). Администратор не может
  менять свои роли и статус; нельзя оставить систему без активного администратора.
- Сессии — в Redis по sha256 идентификатора; cookie `__Host-…` (HttpOnly, Secure, SameSite=Strict). Временная
  cookie входа — SameSite=Lax (иначе не придёт на callback с домена IdP). CSRF: синхронизирующий токен +
  проверка `Origin`/`Sec-Fetch-Site`. Роли читаются из БД на каждый запрос — отзыв прав мгновенный.
- Локальный compose работает по http, поэтому `ADMIN_COOKIE_SECURE=false` только там; в production — ошибка старта.
- Токены покупателей: в проде по умолчанию `CUSTOMER_AUTH_PROVIDER=disabled` (все запросы анонимные) до
  интеграции (открытый вопрос №2); mock с HS256 запрещён в production.

## 2026-09-28 — Матрица прав: дополнения к разделу 2

- Администратор может снять группу с публикации (kill switch отдельной группы, 10.8).
- Статистика доступна аналитику, редактору и публикатору; журнал аудита — администратору.
- Настройки (kill switch, allowlist) видят все роли, меняет только администратор.

## 2026-09-28 — Аудит и хранение

- Аудит append-only: у роли приложения нет UPDATE/DELETE/TRUNCATE, триггер запрещает изменения даже владельцу.
  Удаление записей старше 3 лет — процедура DBA с отключением триггера. TODO(spec): партиционирование по месяцам.
- Сырые события — 30 дней, агрегаты — 2 года (ежедневная задача), оригиналы в quarantine — lifecycle 7 дней.

## 2026-09-28 — Прочее

- Rate limit по IP: `/feed` 600/мин, `/events` 300/мин (за NAT операторов много пользователей на IP);
  при недоступности Redis лимит пропускается (`skipOnError`), лента важнее. Значения — в конфиге.
- Health: `/v1/health` (readiness: БД обязательна, без Redis — `degraded`) и `/v1/health/live`.
- Рабочее время для алерта «публикация вне рабочего времени»: пн–пт 09:00–20:00 МСК. TODO(spec): уточнить у ИБ.
- Локально без Docker интеграционные тесты используют `embedded-postgres` и `redis-memory-server`; S3 в тестах —
  in-memory реализация интерфейса хранилища, реальный S3 проверяется в CI на compose-стенде.

## 2026-09-28 — Веб-плеер: поведение там, где ТЗ молчит

- Тап по средней трети экрана — следующий слайд (как правая треть).
- Группа считается просмотренной при открытии. Превью в админке состояние «просмотрено» не пишет.
- Escape и программное `close()` отправляют `story_close` с `reason=button`; `destroy()` события не шлёт.
- Клик по карточке товара — `story_product_click` и вызов `onCta` с типом `product` (хост открывает товар).
  `story_add_to_cart` — только после успешного `onAddToCart`.
- Таймер слайда-картинки стартует после загрузки изображения; `story_slide_view` — через 1 с после готовности.
  Для видео резервный таймер (длительность + 2 с, стоит на паузе при буферизации) не даёт плееру зависнуть.
- Reduced motion и `autoplay: false`: слайд стартует на паузе; после ручного запуска доигрывается и останавливается.
- Медиа с чужого origin: слайд пропускается, `story_media_error` с `forbidden_origin` — один раз при загрузке ленты.
  Обложка или постер с чужого origin просто не показываются.
- Веб-плеер не шлёт `X-App-Version` (для web сервер его не требует).
- При закрытии страницы события уходят через `navigator.sendBeacon` как JSON с `Content-Type: text/plain` —
  без CORS preflight. `/v1/events` принимает такое тело (разбирает как JSON в пределах 64 КБ).

## 2026-09-28 — Админка

- Раздел «Настройки» видят все роли (право `settings:read`) в режиме чтения — редактор и публикатор знают,
  выключена ли лента и какие домены разрешены. Меняет только администратор.
- 401 — сразу переход на SSO с возвратом на текущую страницу. Если 401 повторился в течение 15 секунд после
  входа, показывается `/login?error=loop` вместо бесконечного цикла редиректов.
- zod в браузере работает в режиме jitless (`disableZodJit()` из `@idb-stories/schema`): иначе проверка
  `new Function` нарушает CSP без `unsafe-eval`.
- Кнопка «Опубликовать сейчас» показывается, когда сервер разрешает ручную публикацию (`actions.canPublish`).
- Живое превью показывает последнюю **сохранённую** версию: перезагружается после сохранения, после обработки
  файла и раз в 10 минут (подписанные URL живут 15 минут).
- Диалог о несохранённых изменениях — внутри приложения; браузерный `beforeunload` не используется.
- В браузере проверяются тип и размер файла до запроса ссылки на загрузку и размеры изображения; длительность
  видео проверяет только воркер (`blob:`-URL запрещены CSP).
- `vite preview` отдаёт тот же строгий CSP, что nginx в проде, — сборку можно проверить на нарушения локально.
